## Problem

Agents burning tokens and round-trips on the adaptive-artifacts CLI: qualified type names on every mutator, mandatory `--expected-revision` with a prior get/list, multi-command view regen, weak list/get output shaping, and store discovery broken by worktrees and a zsh `--store` wrapper. The 2026-10-14 trace synthesis named `bin/aa` plus six concrete runtime areas.

## Approach

**One ship** (decisions: one-ship-scope, expected-revision-default, views-immutability-exempt). Implement `bin/aa` and all six CLI/runtime optimization areas in this phase with additive compatibility: qualified types and explicit revision digests keep working; `--expected-revision` defaults to `@current`; `<store>/views/*.md` are exempt from immutability so view sync and hook-stop coexist. Spec `aa-cli-surface` requirements R1–R7 are the acceptance spine; design `aa-cli-surface` names the surfaces (`bin/`, `tools/artifacts.py`, `tools/runtime/`, `scripts/sync-plugin.sh`, tests).

Session shape: **one sitting** preferred; executor **inline** (tightly coupled CLI surface). Human stops: plan review; Landing merge + store commit on primary.

## Exit criteria

1. `bin/aa` and `adaptive-artifacts` share the same CLI entry — verified by smoke help/version on both after sync-plugin layout.
2. R1–R7 each have automated coverage under `tools/runtime/tests/` — verified by `python3 -m pytest tools/runtime/tests -q` green.
3. create→update without a preceding list/get solely for revision — verified by a test or fixture using default/`@current`.
4. View sync + validate with dirty `views/*.md` succeeds — verified by a validation test for the views exemption.
5. Phase Landing merge + store commit completed on primary.
