## Requirements

R1: Ship `bin/aa` as a same-entrypoint alias for `adaptive-artifacts` (sync via `scripts/sync-plugin.sh` / install paths). Both names invoke the same `tools/artifacts.py` CLI.
R2: Short (unqualified) type, view, and bundle names resolve on every subcommand that takes those ids; ambiguous or unknown names fail with structured `ambiguous_type` / `unknown_type` (or view/bundle equivalents), never silent empty success.
R3: Targeting ergonomics: `--type` optional when `--id` uniquely locates a record; `get`/`update`/`supersede` accept `--type`+`--subject` when exactly one active match exists; `--expected-revision` defaults to `@current` on update/supersede/contradict; `correct` accepts `--expected-revision` as a predecessor concurrency guard.
R4: View sync: a single command writes contract views to `<store>/views/` (e.g. `view --write` or `sync-views`). `validate_immutability` exempts `<store>/views/*.md` so hook-stop can regenerate without an immutability violation on dirty derived views.
R5: List ergonomics: top-level `--where` fields that agents actually need (including subject/lifecycle where safe), `--exact-subject`, expanded `--order-by`, and `--fields` / `--format` output shaping.
R6: Payload/output ergonomics: `get --full` / `--field` / `--body-only`; repeatable `-p`/`--set` and `--payload-file` on mutators; `apply --file` (and stdin) for NDJSON batches.
R7: Store discovery is worktree-aware (same git common dir / binding rules as intended for linked worktrees). Session hooks refuse to overwrite existing view files when a stale plugin read yields zero records.

## Acceptance criteria

1. CLI tests cover short-name resolution success, ambiguity, and unknown for list and at least one mutator.
2. A create→update path works with no prior get/list solely for revision (uses default `@current` or explicit `@current`).
3. `view --write` (or documented sync command) materializes handoff (and other contract views); validate passes with dirty views when only views changed.
4. `python3 -m pytest tools/runtime/tests -q` is green including new coverage for R1–R7.
5. Documented smoke: `aa --help` and `adaptive-artifacts --help` both work from the installed plugin layout.

## Constraints

- Public CLI observable behavior used by se-workflow must stay compatible: old qualified `--type project:…` and explicit `--expected-revision sha256:…` keep working.
- Extension catalog/traits/backends are out of scope unless a test forces a lock bump; this phase edits `bin/`, `tools/artifacts.py`, `tools/runtime/`, `scripts/sync-plugin.sh`, and tests.
- Do not delete or rewrite the continuity archive under `.artifacts/archive/`.

## Non-goals

- Renaming the extension or contract language away from adaptive-artifacts.
- Rewriting se-workflow skills to require short names only.
- Removing the zsh user wrapper from `~/.zshrc` (document conflict only if discovery still fights it).
- Bulk-migrating archived continuity records back into the live store.

## Invariants

- Records remain the authority; views stay derived.
- Unknown type/view/bundle names never return an empty successful list as if the name were valid.
- Conditional writes still honor an explicit expected revision when provided.

## Assumptions

- se-workflow remains the primary in-tree consumer and will adopt new flags opportunistically.
- Human will commit the continuity→se-workflow store cutover so immutability validate can pass on archived deletions.
