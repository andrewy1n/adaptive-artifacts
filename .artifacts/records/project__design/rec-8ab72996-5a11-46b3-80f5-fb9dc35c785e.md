## Architecture

All changes stay in the adaptive-artifacts CLI/runtime surface: `bin/aa` (and sync-plugin), argparse + command handlers in `tools/artifacts.py`, helpers in `tools/runtime/` (query, validation, session hooks, store discovery), and tests under `tools/runtime/tests/`. No catalog/trait redesign. se-workflow keeps calling the same binary; new flags are additive.

## Interfaces

- CLI: `aa` ≡ `adaptive-artifacts`; short type/view/bundle tokens; optional `--type` with `--id`; `--type`+`--subject` targeting; `--expected-revision` default `@current`; `view --write` / sync; list `--exact-subject` / `--fields` / `--format` / richer `--where` & `--order-by`; get `--full`/`--field`/`--body-only`; `-p`/`--set`, `--payload-file`; `apply --file`.
- Validation: `validate_immutability` skips `<store>/views/*.md`.
- Discovery: worktree-aware store root resolution; session_hooks no-clobber when read count is 0 but views already exist.

## Decisions

- one-ship-scope → single-phase-all-six-plus-aa
- expected-revision-default → default-at-current
- views-immutability-exempt → exempt-store-views-md

## Invariants

- Qualified names and explicit revisions remain valid.
- Unknown/ambiguous short names error structurally.
- Records authoritative; views derived.

## Assumptions

- Plugin install continues to sync `bin/` via existing sync-plugin path.
- Cutover commit will clear archive-deletion immutability noise so hook-stop can be used in this repo again.

## Tradeoffs

- One large phase vs staged delivery: chosen for coherent exit criteria and because the human already selected the full set.
- Default `@current` vs required flag: favors agent ergonomics; explicit digest still available for strict OCC.

## Risks

- se-workflow tests that assert exact argv/`required=True` for `--expected-revision` may need updates.
- Views exemption weakens git-based tamper detection for derived files (accepted).
- Worktree discovery must not break the intentional `--store` / `--root` overrides used in CI.
